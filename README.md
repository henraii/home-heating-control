# Гэрийн халаалтын удирдлага

Ч.Эсэн, А.Сүхболд, Энхтөр.Эрхэс

## 1. Төслийн зорилго, шаардлага

**Зорилго:** Хүн гэрт байгаа эсэх болон өрөөний температураас хамаарч халаалтыг ухаалгаар удирддаг систем загварчлах.

**Үндсэн шаардлага**

- Мэдрэгчээс температур, хөдөлгөөн, цагийн мэдээлэл авна (эхэндээ симуляцаар үүсгэнэ).
- HMM нь гэрт хүн байгаа эсэхийн магадлалыг цаг тутам тооцно.
- MDP нь төлөв, үйлдэл, шилжилт, шагналыг тодорхойлно.
- Q-learning нь MDP орчинд суралцаж, халаалтын үйлдлийг сонгоно.
- Систем цаг тутамд шинэ мэдээлэл аваад дахин шийдвэр гаргана.

**Хязгаарлалт**

- Хүн байхад тав тухтай температур: 20–23°C.
- Хүн байхгүй ч өрөө 16°C-ээс доош орохгүй байх.
- Температурын хүрээ: 14–26°C.
- Систем алдаа гаргавал гараар удирдах боломжтой байх.
- Хүний байгаа эсэхийн мэдээллийг гадагш дамжуулахгүй.

**Үнэлэх үзүүлэлт:** эпизодын дундаж шагнал, эрчим хүчний хэрэглээ, тав тухтай температурт байсан хугацаа, HMM-ийн таамаглалын нарийвчлал.

## 2. MDP загвар (`mdp.py`)

- **Төлөв:** (температур, хүн байгаа эсэх) — 13 × 2 = 26 төлөв.
- **Үйлдэл:** бууруулах, хэвийн, нэмэгдүүлэх.
- **Шилжилт (1 цаг):**
  - бууруулах: −1°C (0.7), хэвээр (0.3)
  - хэвийн: −1°C (0.2), хэвээр (0.8)
  - нэмэгдүүлэх: +1°C (0.4), +2°C (0.6)
  - хүн байгаа эсэх 0.95 магадлалтай хэвээр үлдэнэ.
- **Шагнал:** хүн байхад 20–23°C бол +10, гадна бол зайн 2 дахин хасах оноо. Хүн байхгүй үед 16°C-ээс доош бол −5. Эрчим хүчний зардал: бууруулах 0, хэвийн 1, нэмэгдүүлэх 5.
- γ = 0.8. Value iteration-оор оновчтой бодлогыг олж загварыг шалгасан.

| Температур | Хүн байхгүй | Хүн байгаа |
|---|---|---|
| 14–16°C | нэмэгдүүлэх | нэмэгдүүлэх |
| 17°C | хэвийн | нэмэгдүүлэх |
| 18–20°C | бууруулах | нэмэгдүүлэх |
| 21°C | бууруулах | хэвийн |
| 22–26°C | бууруулах | бууруулах |

Хүн байхад 21°C орчимд барьж, хүн байхгүй үед 17°C хүртэл хөргөж эрчим хүч хэмнэж байна. Q-learning (4-р алхам) нь `step()` функцийг орчин болгон ашиглана.

## 3. HMM (`hmm.py`)

- **Нуугдмал төлөв:** хүн байгаа, хүн байхгүй.
- **Ажиглалт:** хөдөлгөөн (байгаа/үгүй), температурын өөрчлөлт (буурсан/тогтвортой/өссөн), цаг (шөнө/өглөө/өдөр/орой). Ажиглалтуудыг бие биенээсээ хамааралгүй гэж үзэж магадлалыг нь үржүүлнэ.
- **Forward алгоритм:** өмнөх магадлал болон шинэ ажиглалтаар хүн байгаа магадлалыг алхам бүрт шинэчилнэ.
- **Viterbi:** бүх дарааллыг харж хамгийн магадлалтай төлөвийн замыг олно.

1000 цагийн симуляцийн үр дүн:

| Арга | Нарийвчлал |
|---|---|
| Зөвхөн хөдөлгөөн мэдрэгч | 0.769 |
| HMM forward | 0.897 |
| HMM Viterbi | 0.916 |

Хөдөлгөөн мэдрэгч хүн байхад ч хөдөлгөөн илрүүлэхгүй байж болдог (жишээ нь унтаж байхад). HMM өмнөх төлөвийг ашигладаг тул ийм алдааг багасгаж байна.
